# KSASNT

[English](README_EN.md) · 中文

基于上下文工程的本地知识库引擎：把 md / txt 文档入仓，按问题预筛、分片、抽取、整合，再给出**带出处**的回答。

**本仓库不开放源代码。** 官方包只出现在 [Releases](../../releases)。

## 它解决什么

多数「知识库」先切向量再找相似段。KSASNT 走的是另一条路：**用上下文工程管住整段阅读预算**——先判断这篇是否值得读，再按块抽取与问题有关的句子，去重合并，最后作答并回写 `[文档:行号]`。

适合已经落在本地的制度、手册、纪要、技术说明，而不是公开网页搜索。

## 处理链路

![从入仓到带出处作答的六步](docs/images/02-pipeline.jpg)

| 步 | 做什么 | 使用者能感到的结果 |
| --- | --- | --- |
| 1 文档入仓 | 读入 md / txt，建成可复用知识库 | 同一批材料能反复问 |
| 2 相关预筛 | 按当前问题丢掉明显无关的篇 | 少跑无用调用 |
| 3 重叠分片 | 固定窗口 + 重叠，避免句子被切断 | 长文不会只看见半段 |
| 4 要点抽取 | 每片只抽出与问题有关的内容并记来源 | 答案能指回原文位置 |
| 5 去重合流 | 合并相近摘录，压进上下文预算 | 不把同一句话贴三遍 |
| 6 带出处作答 | 在合并后的上下文上作答 | 正文旁出现 `[doc:10-15]` |

另有 **忠实原文** 路径：跳过摘要式抽取，只判断相关后把原文片段交给作答（适合「不要改写、对着原文讲」）。

## 三种问法

![精确查询 · 智能问答 · 智能自适应](docs/images/03-modes.jpg)

| 模式 | 适合问 | 回答气质 |
| --- | --- | --- |
| 精确查询 `query` | 数字、条款、有没有某条规定 | 短、对准事实 |
| 智能问答 `qa` | 为什么、原理、怎么理解 | 带背景的说明 |
| 智能自适应 `auto` | 不确定该用哪种 | 按问题类型自行收紧或展开 |

模式写在本机配置里，可改提示词，不必改程序。

## 下载与运行

1. 打开本仓库 **Releases**，下载官方 zip / EXE。
2. 用该版本说明里的 SHA256 校验后再打开。
3. 把 `llmcall.env`（或发行说明指定的环境文件）放在程序能找到的位置，指向你的 Ollama 或兼容接口。
4. 导入 md / txt，建立知识库，再提问。

当前工作区若还没有 Release 资产，说明打包尚未挂上——请等发布者上传，不要在 Issue 里索要源码。

运行时数据默认写在可写目录（程序旁 `data/`，或 `Documents/KSASNT`，写不进去再退到临时目录）。知识库以独立文件保存，删除某个库不会动别的库。

### 本机常见文件

```
ksasnt_config.json     分片大小、并发、模式与提示词
llmcall.env            模型接口（不要提交、不要发到 Issue）
knowledge_bases/       入仓后的库与元信息
ksasnt.log             运行日志
```

## 使用建议

- 单次导入先控制在配置里的文档上限附近，确认预筛和出处再加大。
- `chunk_size` 太大容易撑爆上下文；太小则出处碎。从默认值改，不要一次改两个数量级。
- 并发和 QPS 跟你的模型服务成正比。本地小模型先把并发降到 1–2。
- 答案里没有出处时，先看该模式是不是把无关篇全部预筛掉了，或库根本是空的。
- 这不是法律 / 医疗 / 财务意见。出处方便你回原文核对，不代替核对。

更细的操作说明见 [docs/USER_GUIDE.md](docs/USER_GUIDE.md)。发布者发版步骤见 [docs/PUBLISH.md](docs/PUBLISH.md)。
